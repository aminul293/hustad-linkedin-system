# Program status

Not in this repository, deliberately.

The status doc is the running record of the program: what changed and when, which targets were
removed and why, which name matches still need a human to confirm, what is open. Every one of those
entries names a real person, so it is operational data rather than engineering documentation, and it
follows the same rule as everything else in that class: it lives in `data/work/PROGRAM_STATUS.md`,
which git never sees.

The current copy also lives in the Claude project, `Hustad_LinkedIn_NewBusiness_Program_Status`,
which is where Eric reads it and where the scheduled jobs update it. If you need it, ask him for it
or read it there. If you find yourself wanting to commit a copy so the repo is self-contained, that
is exactly the instinct `docs/PRIVACY.md` is written to talk you out of.

What you probably want instead:

- how the system is built: `docs/ARCHITECTURE.md`
- what the messages must and must not say: `docs/COPY_STANDARD.md`
- what the scheduled jobs do: `docs/SCHEDULED_TASKS.md`
- what to build next: `../NOTES_FOR_AMINUL.md`
